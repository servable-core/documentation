# $ servable auth

Manages the CLI's stored session against the Servable registry (used by `protocol community
use`/`submit`). Credentials are stored locally via the CLI's own store, keyed by the registry host.

## Status
Checks whether the CLI currently holds a stored session.
```bash
servable auth status
```

### Options
N/A

### Example
```bash
servable auth status
```

## Login
Logs into the Servable registry and stores the resulting session.
```bash
servable auth login
```

### Options
```bash
  --registryUsername       Username (stored locally once entered)   [string]
  --registryPassword       Password                                 [string]
  --registrySessionToken   Session token (stored locally once obtained)   [string]
```

These are prompted interactively if not passed as flags; `registryUsername` and
`registrySessionToken` are persisted to the local CLI store so subsequent commands (`auth status`,
`protocol community use`/`submit`) don't need to log in again.

### Example
```bash
servable auth login --registryUsername myemail@gmail.com
```

## Logout
Clears the locally stored session.
```bash
servable auth logout
```

### Options
```bash
  --registryConfirmLogout   Confirm logout   [boolean] [default: false]
```

Prompted as a confirmation if not passed; does nothing if you're not currently logged in. On
confirmation it clears the stored username, password, and session token.

### Example
```bash
servable auth logout
```
