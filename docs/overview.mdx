# Overview

**Servable** is a protocol-oriented Node.js backend framework built on Parse Server. Instead of scattering a capability like comments, follows, or notifications across controllers and models, you write it once as a protocol and attach it to any class that needs it, reusable across models, across projects, and publishable as its own npm package for other teams to use unmodified.

Servable orchestrates the different protocols applied to your models and runs them on a framework engine (currently Parse Server, the only engine implemented today, even though the engine API itself is designed to support others). It does not handle any database or expose any API on its own; that's the engine's job. What Servable adds on top is schema computation from every protocol's declarations, a safe migration path (see [Schema Migrations](./guides/schema-migrations)), and lifecycle wiring (seeding, config, routes, jobs, triggers) so a well-built Servable project ends up being mostly your actual models and business logic.

:::info
Servable is still experimental and its API may change in the future.
:::

![logo](/img/icon.svg)

Highlights:
- Quick start and Plug & Play Node JS framework
- Reusable, composable, publishable protocols instead of scattered controllers/services
- Community protocols
- Schema based models and auto-migration
- Highly extensible

New to Servable, or comparing it against Express, Fastify, NestJS, or plain Parse Server? See
[Servable vs Express, Fastify, NestJS, and plain Parse Server](./concepts/comparison).

## Servable documentation
This is the official documentation site for Servable. Content on this site is sourced in GitHub. For more information, see [Contributing to Servable](./contributing) documentation.

This site is based on [Docusaurus](https://docusaurus.io).

We use the [Diátaxis documentation authoring framework](https://diataxis.fr) which organizes technical documentation into a system based on four quadrants:

- Learning-oriented Tutorials provide hands-on lessons where users can learn the framework by doing.

- Problem-oriented How-to Guides provide recipes to solve specific goals you may encounter while building a LoopBack project.

- Understanding-oriented Concepts pages provide the explanation of architecture concepts, wider view and deeper knowledge about the framework.

- Information-oriented Reference guides provide technical description of the machinery and how to use it.
